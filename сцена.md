# Scene workspace

Эта заметка нужна как быстрый внутренний ориентир по фиче Scene, чтобы не собирать картину заново по кускам.

## Что это

`Scene` — отдельное рабочее пространство рядом с обычным `Chat`.

- `Chat` должен жить как раньше и не смешиваться со сценами.
- `Scene` — полуавтоматическая генерация диалога между двумя персонажами.
- Одна `exchange` / `pair` = две реплики, по одной от каждого персонажа.
- Генерация идет строго по одной реплике за запрос, без параллельных запросов.

## Где смотреть

Основные файлы:

- `public/js/features/scene-controller.js` — связывает Scene с общим приложением, моделями, `sendMessage`, `stopGeneration`, сохранением черновика и UI.
- `public/js/features/scene-state.mjs` — нормализация состояния, enum-ы, вычисление следующего хода, статусы, прогресс beat-ов.
- `public/js/features/scene-runner.mjs` — последовательная оркестрация генерации, cooldown, pause/resume, continue, retry, stop.
- `public/js/features/scene-prompt.mjs` — сборка `instruction` и `prompt` для одного конкретного хода.
- `public/js/features/scene-storage.mjs` — `localStorage`-сохранение черновика сцены.
- `public/js/features/scene-ui.js` — DOM-рендеринг Setup/Run, диалоги персонажей и beat-ов.
- `public/css/features/scene.css` — layout и стили Scene.
- `tests/scene-runner.test.mjs` — регрессии для рискованной логики Scene.
- `tests/chat-prompt-regression.test.mjs` — защита обычного chat prompt от регрессий.

## Какой у Scene state

База создается в `createDefaultSceneDraft()` и хранит:

- `workspace`: `chat | scene`
- `view`: `setup | run`
- `title`
- `globalInstruction`
- `context`
- `model`
- `exchangeCount`
- `firstSpeaker`
- `runMode`: `auto | step`
- `cooldownSeconds`: `2 | 5 | 10`
- `characters.A / characters.B`: `name`, `card`
- `beats`: список режиссерских точек
- `transcript`: уже сгенерированные реплики
- `status`
- `countdownRemainingMs`
- `failedTurn`
- `lastError`
- `pauseRequested`

Ключ хранения сейчас такой:

- `ollama-assistant.scene-draft.v1`

Если страницу обновили во время выполнения, running-state не продолжается автоматически: `normalizeSceneDraft(..., { restoreStopped: true })` переводит активное выполнение в `stopped`.

### Формат реплик в transcript

Каждая реплика в `transcript` теперь живет в двух видах:

- `text` — полный сырой текст ответа модели;
- `blocks` — нормализованный список структурированных блоков в исходном порядке.

Поддерживаются три типа блоков:

- `[SAY]` — произнесенная вслух реплика;
- `[ACTION]` — видимые действия, жесты, мимика, поведение;
- `[THOUGHT]` — приватные внутренние мысли персонажа.

Если модель вернула текст без тегов, используется safe fallback:

- весь ответ трактуется как один блок `[SAY]`.

## Статусы

Поддерживаются явные статусы:

- `draft`
- `generating`
- `coolingDown`
- `paused`
- `waitingForContinue`
- `stopped`
- `completed`
- `error`

Ожидаемая логика:

- после успешной реплики runner решает, это середина пары или конец пары;
- если пара не завершена, сразу идет следующий ход;
- если пара завершена и `runMode=step`, Scene ждет `Continue`;
- если пара завершена и `runMode=auto`, стартует cooldown;
- после последней пары cooldown не ставится;
- при ошибке цикл не продолжается сам, сохраняется `failedTurn`;
- `Retry` повторяет только упавший ход;
- `Stop` обязан гасить и таймеры, и дальнейшие автозапуски.

## Как собирается запрос

На каждый ход `buildSceneTurnRequest()` формирует два блока:

- `instruction`
- `prompt`

Порядок важен:

1. `Global scene instruction`
2. указание кто текущий персонаж
3. требование держаться только его POV и голоса
4. разрешение включать реплики, мысли и описания действий текущего персонажа
5. запрет писать реплики, мысли и действия второго персонажа
6. требование вернуть ответ только tagged-блоками `[SAY]`, `[ACTION]`, `[THOUGHT]`
7. правило, что `THOUGHT` приватен и невидим второму персонажу
8. `Character card`

`globalInstruction` идет первым именно как общий system-level приоритет для каждого хода.

В `prompt` подмешиваются:

- `Scene title`
- `Scene context`
- номер текущей пары
- стабильный порядок говорящих в каждой паре
- текущий говорящий
- director beat только для нужного момента
- весь накопленный диалог
- просьба продолжить сцену, не говоря за второго персонажа

История для текущего хода теперь собирается без мыслей:

- в model-context для обоих персонажей попадают только `[SAY]` и `[ACTION]`;
- `[THOUGHT]` хранится в transcript и показывается в UI, но не отправляется в следующие model turns вообще;
- это убирает "телепатию" и не дает моделям опираться на чужие или даже свои прошлые внутренние мысли как на общедоступный факт;
- порядок видимых блоков внутри каждой реплики сохраняется.

Важно:

- прошлые beat-ы не тащатся как отдельные инструкции в будущие ходы;
- их последствия живут только через уже накопленный `transcript`;
- beat `pair` применяется к обеим репликам пары;
- `beforeA` и `beforeB` зависят именно от персонажа хода, а не просто от первой/второй позиции.
- один ответ модели может содержать несколько блоков одного и того же типа.

## Что видно в UI

Есть две фазы:

- `Setup`
- `Run`

### Setup

Содержит:

- `Characters` — две компактные карточки `A` и `B`, полное редактирование через dialog
- `Scene` — title, global instruction, context, shared model, exchange count, first speaker, run mode, cooldown
- `Direction` — список beat-ов с сортировкой по `pairNumber` и `moment`

Подсказки в пустых карточках сейчас напоминают:

- `Character A` — male character
- `Character B` — female character

### Run

Показывает:

- title
- pair progress
- текущий статус
- current speaker
- transcript
- countdown во время cooldown
- beat list со статусами `completed / current / upcoming`
- действия `Pause/Resume`, `Continue`, `Retry`, `Stop`

На мобильном beat list вынесен в отдельный collapsible-блок, а основная панель действий закреплена снизу.

## Важные UX-детали

- Setup и Run не показываются одновременно.
- Scene использует отдельный workspace switcher `Chat / Scene`.
- Обычный чат не должен терять свое старое поведение.
- Черновик Scene живет отдельно и не трогает chat history.
- Компактные карточки персонажей не держат полный текст постоянно на экране.
- Выбор модели вынесен из карточек персонажей в общий блок `Scene`, потому что в текущей версии обе роли используют одну общую модель.

## Отрисовка реплик

Transcript больше не рисуется как один markdown-кусок.

Текущее правило оформления:

- `[SAY]` — обычный текст реплики;
- `[ACTION]` — жирный текст с цветовым акцентом персонажа;
- `[THOUGHT]` — italic, не жирный, с цветовым акцентом персонажа;
- блоки внутри одной реплики показываются по порядку, каждый отдельно;
- у `Character A` accent идет через `--context`;
- у `Character B` accent идет через `--accent`.

Это сделано специально, чтобы действия и мысли были читаемы сразу, но обычный spoken dialogue не превращался в сплошной цветной текст. При этом `[THOUGHT]` остается только UI-слоем и не уходит обратно в модель как часть последующего контекста.

## Что уже тестами прикрыто

В `tests/scene-runner.test.mjs` уже есть проверки на:

- чередование персонажей;
- выбор первого говорящего;
- точное количество реплик;
- применение beat-ов только в нужный ход;
- global instruction в начале system prompt;
- cooldown только после полной пары;
- отсутствие cooldown после последней пары;
- pause/resume countdown;
- stop во время countdown;
- stop во время запроса;
- отсутствие перекрывающихся запросов;
- retry только неудавшегося хода;
- step-by-step режим;
- восстановление остановленного draft после reload.

Дополнительно есть проверки на:

- парсинг tagged-блоков с сохранением порядка;
- fallback без тегов в один `[SAY]`;
- приватность `[THOUGHT]` при сборке истории для другого персонажа.

## Практическая памятка перед правками

Если нужно что-то менять в Scene, обычно быстрее идти так:

1. `scene-state.mjs` — понять shape state и вычисления.
2. `scene-runner.mjs` — проверить переходы состояний и таймеры.
3. `scene-prompt.mjs` — проверить, что именно уходит модели.
4. `scene-controller.js` — проверить wiring с API и app shell.
5. `scene-ui.js` + `public/css/features/scene.css` — уже потом править интерфейс.

Если баг выглядит как регресс обычного чата, сначала проверить, не потянула ли Scene что-то в общие модули вроде `main.js`, `ui.js` или shared rendering.
